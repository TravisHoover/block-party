# Block Party — working notes

An ad-free iOS block puzzle game (SwiftUI, iOS 17+), built by Travis for his
daughter after the ads in similar games proved unsuitable. No ads, no IAP, no
analytics, no network access — that constraint is the entire point of the app
and should never be traded away for convenience.

## Layout

| Path | What it is |
| --- | --- |
| `BlockParty/GameEngine.swift` | All rules: board state, placement, line clearing, scoring, combos, game over |
| `BlockParty/PieceLibrary.swift` | Piece shapes, `BlockColor` palette, weighted random generation |
| `BlockParty/GameView.swift` | Main screen, drag-and-drop handling, tray, settings sheet |
| `BlockParty/BoardView.swift` | 8×8 grid, block rendering, ghost preview, clear animations |
| `BlockParty/GameOverView.swift` | End-of-game overlay |
| `BlockParty/Haptics.swift` | Haptic feedback wrappers |
| `marketing/` | App Store listing copy + screenshots |
| `.github/workflows/release.yml` | Tag → build → sign → upload to App Store Connect |

Open `BlockParty.xcodeproj` in Xcode. There is no test target and no PR CI —
the release workflow only runs on `v*` tags or manual dispatch.

## Conventions

- Work on a branch, open a PR. Travis reviews before merging; don't push to `main`.
- Don't create a PR unless the work is actually finished.
- Comments explain *why*, not *what*. Match the existing density.

## Hard-won gotchas — read before touching these areas

**Drag and drop.** Placement is computed in **global screen coordinates**, and
the board's frame reaches `GameView` by writing directly to a `@Binding` from
the grid's own `GeometryReader` (`onAppear` + `onChange`). An earlier version
used a named coordinate space, and another used a `PreferenceKey` — **both
silently failed on device**, leaving the board frame unset so every drop was
rejected while working fine in the simulator. Do not reintroduce either.
Grid math also derives cell size from the *measured* frame, not the computed
layout value, so it can't drift from what's rendered.

**`BlockColor` raw values are persisted** (once PR #8 lands, in saved games).
Never reorder or remove cases; only append.

**CI must use the latest stable Xcode.** Apple periodically raises the minimum
SDK for App Store submission and rejects older builds at the *export* step with
a confusing "SDK version issue" message. The workflow uses
`maxim-lobanov/setup-xcode@v1` with `latest-stable` rather than a pin.

**`ASC_API_KEY_P8` is plain text, not base64.** Apple's `.p8` is already PEM
(`-----BEGIN PRIVATE KEY-----`). Base64-encoding it into the secret caused
`keyPathInvalid`. `DIST_CERT_P12_BASE64` *is* binary and does need encoding.

**The App Store Connect API key needs the Admin role.** With App Manager,
`-exportArchive` fails with "Cloud signing permission error / No profiles
found" because automatic signing can't create provisioning profiles.

**Asset generators are gone.** The icon, sound effects, and marketing
screenshots were generated by throwaway Python/Playwright scripts in an
ephemeral scratchpad that has since been wiped. The committed outputs are the
source of truth. Sounds are synthesized bell/sweep tones stored as
asset-catalog **data sets** (loaded via `NSDataAsset`, so adding one needs no
project-file resource changes). For new screenshots, prefer the real iOS
Simulator (⌘S) over recreating the HTML mock.

## Release process

1. Merge to `main`.
2. Bump `MARKETING_VERSION` in `BlockParty.xcodeproj/project.pbxproj` if the
   store version is changing. The build number comes from the CI run number.
3. `git tag v1.2.3 && git push origin v1.2.3` (or run the workflow manually).
4. ~10 min later the build appears in App Store Connect → TestFlight.
5. Attach it to the version page and submit.

Required repo secrets are documented in the README's publishing section.
